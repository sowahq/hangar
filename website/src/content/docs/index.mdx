## Why Hangar

<CardGrid>
  <Card title="Content-addressed chunks" icon="seti:db">
    Blake3-hashed, zstd-compressed chunks on Pebble. Same bytes uploaded twice cost the disk once.
  </Card>
  <Card title="S3-compatible API" icon="cloud-download">
    SigV4 (header + presigned + `aws-chunked`), path-style, multipart, `CopyObject`, `DeleteObjects`, `ListObjectsV2`, lifecycle, CORS, checksum echo. Drop-in for most SDKs.
  </Card>
  <Card title="Encryption at rest" icon="seti:lock">
    SSE-S3 (AES-256-GCM, server master key, HKDF per object, rotatable keyring) and SSE-C (customer-supplied key, server stores only MD5).
  </Card>
  <Card title="Per-bucket auth" icon="approve-check-circle">
    Argon2id tokens with `read` / `write` / `delete` / `admin` scopes. SigV4 over `S3Key` credentials with optional per-bucket restriction.
  </Card>
  <Card title="Operations built in" icon="setting">
    Consistent backup/restore CLI, integrity scrub, background GC, disk safeguards, lifecycle expiration, JSONL audit log with rotation.
  </Card>
  <Card title="Observability" icon="rocket">
    Opt-in Prometheus on a separate port (requests, GC, scrub, disk, multipart). Deep `/status` probe.
  </Card>
</CardGrid>

## Honest status

Pre-1.0. **Single-node today** — distribution, replication, and erasure coding are [planned](/roadmap/) but not built. Read [Limitations](/limitations/) before adopting.

## In 30 seconds

```sh
# build + run
make build
./bin/hangar server -c config.toml

# create a bucket
curl -X PUT http://localhost:8080/admin/buckets/photos

# issue a token, then upload
curl -X POST http://localhost:8080/admin/buckets/photos/tokens \
  -H 'Content-Type: application/json' -d '{"permissions":["write","read"]}'

curl -X PUT http://localhost:8080/photos/img.jpg \
  -H "Authorization: Bearer <token>" \
  --data-binary @img.jpg
```

See [Getting Started](/getting-started/) for the full walkthrough.
