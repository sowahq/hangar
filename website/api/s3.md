# S3 API

Hangar exposes a SigV4-authenticated S3-compatible API on a separate port. Most AWS SDKs work out of the box with `path-style` addressing.

Enable it in `config.toml`:

```toml
[s3]
enabled   = true
bind_addr = ":9000"
region    = "us-east-1"
```

## Credentials

Create an S3 access key through the admin API:

```sh
curl -X POST http://localhost:8080/admin/s3keys \
  -H 'Content-Type: application/json' \
  -d '{"permissions":["admin"]}'
```

Response:

```json
{
  "access_key_id": "GRYGVH4K6YYNKMUEUXG5",
  "secret_key": "DRSOnIeyYoCy+xuFBUVI6u6mBOJxdz0i9coWhNb0",
  "permissions": ["admin"],
  "buckets": []
}
```

Restrict to specific buckets by passing `"buckets": ["photos","logs"]`.

## SDK setup

=== "AWS CLI"

    ```sh
    aws configure --profile hangar
    # access key + secret from above

    aws --profile hangar \
        --endpoint-url http://localhost:9000 \
        s3 ls
    ```

=== "Go (aws-sdk-go-v2)"

    ```go
    cfg, _ := config.LoadDefaultConfig(ctx,
        config.WithRegion("us-east-1"),
        config.WithCredentialsProvider(credentials.NewStaticCredentialsProvider(ak, sk, "")),
    )
    cli := s3.NewFromConfig(cfg, func(o *s3.Options) {
        o.BaseEndpoint = aws.String("http://localhost:9000")
        o.UsePathStyle = true
    })
    ```

=== "Python (boto3)"

    ```python
    import boto3
    s3 = boto3.client(
        "s3",
        endpoint_url="http://localhost:9000",
        aws_access_key_id=ak,
        aws_secret_access_key=sk,
        region_name="us-east-1",
        config=boto3.session.Config(s3={"addressing_style": "path"}),
    )
    ```

## Supported operations

| Operation                | Notes                                                  |
|--------------------------|--------------------------------------------------------|
| `ListBuckets`            |                                                        |
| `CreateBucket` (`PUT /:bucket`)         |                                         |
| `DeleteBucket`           | Must be empty                                          |
| `HeadBucket`             |                                                        |
| `PutObject`              | Including `aws-chunked` streaming payload              |
| `GetObject`              | Supports `Range`, `If-Modified-Since`                  |
| `HeadObject`             |                                                        |
| `DeleteObject`           |                                                        |
| `DeleteObjects` (batch)  |                                                        |
| `CopyObject`             | Chunk-ref reuse when unencrypted, re-encrypt on SSE    |
| `ListObjectsV2`          | `prefix`, `delimiter`, `start-after`, `continuation-token` |
| `CreateMultipartUpload` / `UploadPart` / `CompleteMultipartUpload` / `AbortMultipartUpload` / `ListMultipartUploads` / `ListParts` |  |
| Presigned URLs (`X-Amz-*` query)        | GET and PUT                              |

## Encryption headers

Standard SSE headers are honored:

- `x-amz-server-side-encryption: AES256` → SSE-S3 (requires master key configured)
- `x-amz-server-side-encryption-customer-algorithm` + `-customer-key` + `-customer-key-MD5` → SSE-C

See [Encryption](../sse.md) for details and the error matrix.

## Addressing

Path-style only today (`http://host:9000/bucket/key`). Virtual-host style (`http://bucket.host:9000/key`) is not yet supported — configure your SDK with `UsePathStyle: true` or the equivalent.

## Not yet supported

- ACLs / bucket policies
- Object Lock / WORM
- Lifecycle rules
- SSE-KMS
- Bucket default encryption config
- `x-amz-checksum-*` response echo (AWS SDK may emit a "no supported checksum" warning — payload integrity still validated via ETag)
